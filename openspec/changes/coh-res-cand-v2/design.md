## Decisions

**D1. C#-only, behind a setting, default OFF.** OFF is today's code on every path: no extra snapshot (`captureCohSnapshot` is false), no third run, and the coherent-fallback log line is byte-identical to `70bc72b1` (the new fields are appended only while the setting is effective). Acceptance row B-OFF compares 40 cycles field by field against the CQ-AP OFF arm.

**D2. What was taken from `b0d01f4f` (#272).** The snapshot plumbing, re-applied (the base differs, so by hand, not by cherry-pick): `DecoderConfig` property and constructor parameter; `SubtractionPass` (`captureCohSnapshot`, `PassStats.CaptureCohSnapshot` / `CohSnapshot`, `ResidualPassReport.CohSnapshot`, `ThirdPassResult.CohSnapshot`, the snapshot call after `DecodeAll(residual)`); `CohFallbackAudioSelector.Choice.CohSnapshot`; the setter, getter and daemon wiring. **Not taken:** the `fallback-orig` substitution, the resCand counters, `CohFallbackEligibleCount` (interface and adapter) and `origEligible`: #272 REPLACED the second run's list, v2 adds a run, so the first two runs keep `cohSnapshot` and need none of them.

**D3. R2 questions, re-confirmed on this base.** (a) The snapshot is complete with diagnostics off: the residual `DecodeAll` runs with `SetDiagnosticsEnabled(false)` (`SubtractionPass.cs:458`, call at `:463`); in `ft8_shim.c` the candidate list is recorded at `:1993-1998` and the decoded payloads at `:2027-2030`, BEFORE the diagnostics switch is consulted at `:2039` (`if (!tls_diagnostics_enabled) continue;`), which skips only the LDPC-failure sums. (b) How a run uses a snapshot's payloads: `ft8_coherent_fallback_run` marks a CRC-valid result `KNOWN` (and does not publish it) when its payload equals one in `snap->payloads` (`ft8_shim.c:2769-2772`, and `:2936` in the multi-set walk). The residual snapshot holds the payloads decoded on the residual buffer, not pass 0's, so a payload published in batches 1 to 3 can be re-found by the third run as `NewGated`. Guards: the text is already in `seen` and so is not "new text" (it is not gated, counted or published again), and `MapNative` de-duplicates by text.

**D4. One call site for R2 and R3.** Both the residual pass and the third pass reach `interop.DecodeAll(residual)` (`SubtractionPass.cs:463`) inside `RunCoreUnguarded`, on the pass's own `Task.Run` thread. The snapshot is taken there, immediately after the call (the native candidate list is thread-local and reset by the next `ft8_decode_all`), and carried out through `PassStats` into `ResidualPassReport` (R2) and `ThirdPassResult` (R3). `CohFallbackAudioSelector.Select` returns the pair of the buffer it chooses, so list and audio cannot come from different buffers. A snapshot call that throws is contained; the pass keeps its decodes and the third run is logged `resRun=no-snapshot`.

**D5. The third run (R3).** After the second run, `leftAfterSecondMs = budgetMs - (sw.Elapsed - fbStart)` (the same arithmetic as the second run's `leftMs`). `<= 0`: `resRun=skipped-budget`. No residual buffer: `no-residual` (`resCand=none`). First run failed (null): the third run is not started, nothing throws, and no line is written (the cycle publishes nothing, as today). Snapshot missing: `no-snapshot`. The third run's own failure (null result): `failed`, the first two runs' rows are published as without the setting. Otherwise `ran`. Four of these are the spec's tokens; `failed` is the one state the spec left unnamed.

**D6. R-F4 never ungates the third run (R3).** `ungatedOn` (R-F4) acts in exactly one place: `CohFallbackAudioSelector.Merge(originalRows, residualRows, ungatedOn)` sets `Admitted = true` on the RESIDUAL run's `GatedOut` rows (`CohFallbackAudioSelector.cs`, the `admitResidualGatedOut` line), and `CohFallbackRow.IsPublishable` reads that flag. The third run's rows are never passed to `Merge`. They enter publication through `CohFallbackAudioSelector.ThirdRunCandidates`, which keeps `State == NewGated` rows only (F1b at or below T1) and then applies `CoherentFallbackSelector.Select`'s one-row-per-payload, non-edge-first rule. A `GatedOut` row of the third run therefore never publishes, whatever the setting of R-F4. No change to `Merge` or to what R-F4 does for the first two runs.

**D7. The gate (R4).** The published integer Hz is formed in ONE place, `CohFallbackAudioSelector.PublishedFreqHz(row) = (int)Math.Round(row.OutFreqHz)`; the first two runs' natives and the third run's both take their `FreqHz` from it, `MapNative` copies `nr.FreqHz` unchanged into `DecodeResult.FreqHz` (`Ft8Decoder.cs`, the `FreqHz: nr.FreqHz` line), and that is the `freq` the replay harness writes. The gate is `PassesResidualRunGate(publishedHz) = publishedHz <= ResidualRunMaxFreqHz (1097)`, applied to that same integer. It applies only to a new-text row: a row whose text is in `seen` (batches 1 to 3) or among the first two runs' texts is not new, is neither gated nor counted, and `MapNative` would drop it anyway.

**D8. Order and de-duplication (R5).** Kept third-run rows are appended after the first two runs' rows, so they can never displace one (B-KEEP). They go through the same `MapNative` (per-cycle text de-duplication, plausibility filter, L1' kept-natives list). A third-run row with the same payload as a published first-two row is skipped before its text is unpacked. Unpacking a third-run row's text is an ordinary `CohFallbackUnpack` call and may insert a hashed call into the process-global hash table; B-KEEP allows the resulting re-rendering of a later hashed-call row (same freq and dt).

**D9. Log (R6).** Appended to the existing line, only while `resCandOn` (setting ON, fallback running, `Both` mode): `resRun`, `resCand`, `resEligible` (the third run's eligible count; 0 when it did not run), `resNew`, `resNewGated`, `resNewKept`, `resWallMs`. The line's existing fields describe the first two runs only (the third run's counts are not added to `eligible` / `attempted` / `crcOk`), but `published`, `fbWallMs` and `batch4Published` include what the third run added. Aggregates only (NFR-021, HK-037).

## Risks

- The third run costs wall time (about one run, perhaps 0.3 to 0.5 s) before L1' starts. Mitigation: B-AB and B-LATE; NET already prices a lost row.
- The gate is fitted on 19 tested_absent rows of another band and configuration, with no known mechanism. Mitigation: Stage 2 on a night it never saw; the verdict is registered before the data.
- The residual run re-finds a batch-1 to 3 payload not marked `KNOWN` (D3). Mitigation: text de-duplication; row B-DUP; a test pins it.
- A native-thread mistake (snapshot on the wrong thread). Mitigation: D4; the test records which `DecodeAll` each snapshot followed and which snapshot each run received.
