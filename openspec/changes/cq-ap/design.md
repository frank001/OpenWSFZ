## Decisions

- **Where the attempt sits.** In `ft8_decode_all`, inside the `decoded` determination and **before** the `if (!decoded) { ...; continue; }` branch. A CQ-AP decode therefore goes through the cross-pass dedup (hash and payload), `ftx_message_decode`, the hash handling and `results[]` like any other, and it sets the candidate's coherent-fallback record (`tls_cf_cands[].decoded`) and stores its payload, so the coherent fallback does not retry it. A decode the normal attempt makes is never replaced and its candidate is never counted as a CQ-AP attempt.
- **Injection after normalisation (Architect Amendment 1, A1.2).** The QSO-AP mechanism overrides at +-40 *before* `ftx_normalize_logl`; the normaliser's variance then includes the forced values, so 32 of them inflate it and scale the other 142 LLRs down before BP, which is not scale-invariant. CQ-AP normalises the raw LLRs first, then writes the 32 forced positions at `1.01 x max |LLR|` of the normalised non-forced entries. QSO-AP's own scaling is left exactly as it is (observation O2, out of scope).
- **The forced bits come from the encoder, not from a constant.** The pattern is read out of ft8_lib's own encoding of `CQ Q1ABC JO22` (payload bits 0 to 28 and 74 to 76; 32 positions, no others), so the c28 of the token `CQ` is the encoder's, not a retyped 2. Sign convention is `bp_decode`'s: bit 1 is a positive LLR. A unit test encodes the message and asserts every forced position equals the encoded bit and that exactly 32 are forced (E151/E152 are why this is a test and not a reading).
- **BP only, with a counter that can count.** The shared core (`cq_ap_core`) takes an `allow_osd` parameter ONLY so a test can prove the OSD counter counts; the production function passes the literal 0 and nothing else does. The counter is a thread-local with a getter. QSO-AP keeps its OSD fallback.
- **The per-call flag is thread-local, in the same bracket as the AP bits.** `ft8_set_cq_ap` is set on the decoding thread right before every `ft8_decode_all` (the managed caller sets it every time, so a pool thread cannot carry a stale value) and cleared where the thread is reused. It is not a process-global. It is read once per cycle by `Ft8Decoder` and travels in a per-cycle `CqApCycleCounters` to pass 0, the residual pass, the third pass and the late round.
- **`apKind` through an index-aligned getter, not a wider struct.** `FT8Result` is 48 bytes and Python ctypes harnesses allocate arrays of it, so widening it would break their buffers. `ft8_get_last_ap_kinds` is index-aligned with `results[]` (the same contract as `ft8_get_last_snr_terms`); `Ft8LibInterop.DecodeAll` joins it onto the managed `Ft8NativeResult` (which is no longer the marshalled type: the wire type is `Ft8NativeResultWire`, still 48 bytes). New interface members have default implementations so existing test fakes need no change.
- **PSK Reporter.** The `ap=` exclusion is checked first in the ingest loop, so a CQ-AP decode is counted there whatever else would exclude it. It is a count, not a refusal reason. `psk-reporter-upload` is still an active change; its accounting requirement absorbs `ap=` when it is archived (this change's delta states the new behaviour on its own).
- **The log line counts decodes where they are published** (past the plausibility filter and the text de-duplication), and attempts where they are made (summed over every native decode of the cycle). Counts only, never a callsign or message text (HK-037, NFR-021). The early decode (a partial-audio pass 0) writes no line: it would be a second line for one cycle.

## Provenance

`FT8_SHIM_VERSION` 20260072. It identifies nothing: the SHA-256 of the built `libft8.dll` is what the arms pin. The committed Linux and macOS binaries are refreshed by the usual follow-up chore after the native merge (as PR #254 did for 20260069); until then CI rebuilds them.
