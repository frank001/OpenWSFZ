## Context

PSK Reporter accepts reception reports as UDP datagrams in a simplified IPFIX format (`https://pskreporter.info/pskdev.html`, read raw by QA on 2026-10-25, 27,434 bytes). A datagram holds a header, optionally the record format descriptors ("templates"), one receiver record and the sender records. The reference for the bytes is the page plus QA's fixtures in `qa/rr-study/psk-reporter-262/` (`build_t1_fixture.py` reproduces the page's own two worked datagrams byte for byte, then builds the three T1 fixtures with Q-prefix calls). The Architect's build spec is `arch/psk-reporter-262` (`8a83507c`, §10 `a23c19b5`, Amendment 1 `c6f9712f`); where §1 to §10 and Amendment 1 differ, Amendment 1 wins.

## Decisions

1. **The wire format is the fixtures, not a prose list.** The 8-field sender descriptor's order on the wire is `senderCallsign, frequency, sNR, iMD, mode, informationSource, senderLocator, flowStartSeconds` (the locator before the start time); the receiver descriptor is set id 3 with scope-field count 1; the sender descriptors are set id 2. A prose list of fields was wrong once already (Architect ledger E69); the golden test T1 compares with the hand-built fixture bytes.
2. **Two sender templates in one datagram.** D4 gives records with a locator (`0x9993`, 8 fields) and without (`0x9994`, 7 fields). A datagram carries one block per template that has records. The page shows no datagram with two sender blocks: live test L1 checks that the test listener parses both, and a rejection **stops the work and returns to the Architect** (no workaround is invented).
3. **Strict sender extraction, by classification.** A token is a callsign if it has a digit and a letter (with optional `/` parts), a hash if in angle brackets, a CQ modifier if 1 to 4 letters or 3 digits, a grid if `[A-R]{2}[0-9]{2}` and not `RR73`. The existing `Ft8Decoder.ExtractPrimaryCallsignToken` (`Ft8Decoder.cs:1664-1689`) is for the region lookup: it counts tokens, falls back to token 0 and strips suffixes, all wrong for a public spot; it is left untouched. The new extractor lives where the Developer chooses (the service or a small static class), is pure, and has the T4 table.
4. **Dial frequency at capture.** `DecodePump` has the cycle's `dialFreq` (`DecodePump.cs:125`) and passes it to `PublishFirstAsync` and `PublishSecondAsync` (`:197`, `:240`); `DecodeBatch` gains a nullable member (default null so every existing construction compiles) set by the pump. A null dial frequency reports nothing (counted). This sidesteps issue #260 (today's Status uses the current dial frequency, `ExternalReportingService.cs:603-609`).
5. **Own channel.** The reporting service does not share the capacity-2 `externalReportingChannel` (`Program.cs:357`); a fallback-on cycle delivers up to 4 batches. `LateBatch.CreateQsoQueue` (`LateBatch.cs:97`, returning a `QsoBatchQueue`) already encodes the rule (4 x 2 + 2 = 10 with the fallback on, 8 off); reuse it if its shape fits, otherwise a bounded `DropOldest` channel with the same capacity function. The pump's `DecodePumpDeps` (`DecodePump.cs:27` lists the writers) gains the new writer, with a default so existing fixtures compile.
6. **Dedup and cadence are the page's, as decision values.** Per call at least 5 minutes between records; per (call, band) one record per 60 minutes (page: "no more than once per five minute period ... ideally once per hour unless changed", a band move being its example). One datagram per 5 minutes from a timer started at service start with a random 0 to 60 s offset (page: not synchronised to the clock); a full datagram goes at once. The 1,400-byte limit is derived from a 1,500-byte Ethernet MTU minus IP/UDP headers and margin; it is not on the page.
7. **Sequence number** starts at 0 for each process and counts sender records actually sent; the receiver record is not counted; an unsent datagram does not advance it. The page says "count of reports" and shows 1 and 4 in its examples without defining the start: this is a stated decision value.
8. **One IPv4 source port.** The page asks for the same UDP source port on every datagram. One socket is created per enable through an injected factory, re-created only after `enabled` goes false and then true, never bound to 4739.
9. **Identity guard.** `tx.callsign` defaults to `Q1OFZ` and `tx.grid` to `JO33` (`TxConfig.cs:81`, `:87`: "replace before operating"). With an empty or Q-prefix call or an empty locator the service sends nothing and says so once per window as a count.
10. **Failure isolation.** Errors never reach the pump; Warning once per window; bounded queue, oldest dropped and counted; nothing on disk.
11. **Counts, never calls, in logs.** One Information line per datagram: UTC, records in it, exclusions by reason, sequence after.
12. **Config and overlay.** A `PskReporterConfig` record in `AppConfig`, registered in `ConfigJsonContext` and `AppJsonContext`; the explicit section list in `ConfigOverlay.Apply` and `NonNullableSections` (`ConfigOverlay.cs:42-50`, `:70-83`) must include it, with the class test that covers new sections. The overlay merges nested objects, so a POST of `{"pskReporter":{"antennaInformation":"X"}}` keeps `enabled`, `host`, `port`.
13. **iMD is a constant 0.** OpenWSFZ does not measure intermodulation distortion; the Captain chose to send 0 knowing it is published as data (D4). The code comment and the capability spec say so.
14. **L3 outside check.** The retrieve API's default cap and window are partly unmeasured: QA's L3 uses `receiverCallsign` with `rronly=1`, `noactive=1` and a raised `rptlimit`, states the expected count before the run, and treats a count at the cap as INCONCLUSIVE.

## Risks

- **Two sender blocks may be rejected by the server** (decision 2). Mitigation: L1 on the test listener first; stop and return to the Architect.
- **Public false spots.** A false decode becomes a public spot. The strict extractor, the region exclusion, and the F1b-gated fallback bound it; the Captain accepted all batches 1 to 4 (D2). QA reports counts only.
- **Double uploading** if WSJT-X's "Enable PSK Reporter Spotting" is also on under the same call: an operational rule (one uploader at a time), not code.
- **A silent drift of the encoder.** T1 compares with bytes built independently of the code under test; a change of the encoder that changes bytes must change the fixture knowingly.
