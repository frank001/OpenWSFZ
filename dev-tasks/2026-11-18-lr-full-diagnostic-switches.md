## 0. Why

QA's replay harness cannot run the two steps the LR-FULL arm tests, and the spec withdrew route R-H after QA's (k) (`qa/rr-study/2026-11-18-0914-qa-lr-full-k-review.md`, `eb14ebd6`):

- **X1** = v2's third coherent-fallback run **without the 1097 Hz gate**. The gate is `internal const int ResidualRunMaxFreqHz = 1097` (`src/OpenWSFZ.Ft8/Subfeas/CohFallbackAudioSelector.cs:74`, test `:83`), applied inline at `src/OpenWSFZ.Ft8/Ft8Decoder.cs:1617` (`if (!CohFallbackAudioSelector.PassesResidualRunGate(publishedHz)) { resNewGated++; continue; }`). A compile-time const cannot be changed from a harness.
- **X2** = LATE-SUB's **L2**: a coherent-fallback run on the late round's own residual buffer with that buffer's own candidate snapshot. **The product has no such step.** `RunLateRoundAsync` (`Ft8Decoder.cs:1232-1309`) runs the primary decoder's third pass on R3/R2 (fit = batch 3 kept + batch 4 kept) and publishes batch 5. Its residual (`ThirdPassResult.Residual`, `SubtractionPass.cs:214`) and snapshot (`.CohSnapshot`) exist only if the pass was asked to capture them.

(**Naming:** "R4" below is LATE-SUB's name for the late round's residual buffer, *not* the COH-RES-CAND requirement R4 that appears in code comments.)

These are **diagnostic switches for QA's replay**, not product features. Default OFF everywhere, config file and API only (no UI, no docs beyond the config reference, no default-ON proposal).
