## 0. Why (one paragraph)

At WSJT-X's positions on one 40 m night, where the shipped extractor and today's coherent fallback both fail, four further coherent bit-metric sets tried in a fixed order (C1, J2, J3, N1) recovered +2.115 pp of WSJT-X's decodes. This change puts that walk into the fallback behind a default-off flag so QA can replay it on the product's own candidates (with the F1b gate on the outputs) and the Captain can decide later whether it should ever be on.

### Stage 1: the native core and a diagnostic export (no product wiring). Hand back for QA's B1 before Stage 2.

1. **The four sets**, ported **exactly** from `ms_metrics.py`: C1 (order 1 on power, as `coherent_extract.py`'s V1), J2 (joint pairs), J3 (joint triples), N1 (order 1 on magnitudes, each bit divided by the larger of its two maxima, 0 if both are 0). Grouping: the 58 data symbols form two halves of 29 (symbols 7-35 and 43-71); J2 splits each half into consecutive non-overlapping pairs and the 29th symbol is a group of one; J3 splits each half into consecutive non-overlapping triples and the last two symbols form a pair; groups never straddle a Costas block. Score for a group: the magnitude `|sum X[s_j][tone_j]|` over the 8^n tone hypotheses. Bit value: max over hypotheses where the bit is 1 minus max where it is 0, with the Gray map (0,1,3,2,5,6,4,7). Sign: positive = bit 1. Bit order: data symbol k = 0..57, three bits each, gray-index bit2, bit1, bit0. **Doubles**, as `cf_v3_llrs`. An equivalent but faster computation (e.g. an exact rearrangement of the J3 max-log over 512 hypotheses) is allowed **only if B1 passes**.
2. **Input:** the per-symbol correlations `c->x_re / c->x_im` that `cf_v3_llrs` has just computed (`coherent_fallback.c:392-416`), at the same fine-sync estimate. No second downconversion, no second estimate.
3. **The diagnostic export** (name yours, e.g. `ft8_coherent_fallback_sets_at`): takes `(pcm, f0, t0)` as `ft8_coherent_fallback_at` and returns the estimate; V3's BP outcome; for **each** of C1, J2, J3, N1 its 174 raw values, BP rc, CRC flag and payload, **computed for every set whatever the walk does**; and the walk's result (which set, which payload). Existing exports' contracts and struct layouts are unchanged; a new field goes in a new struct or an appended field with the C# side changed in the same commit, a size assertion and a test.
4. `FT8_SHIM_VERSION` **20260071** with a history entry.
5. **Tests first (B2):** J2 = 15 groups per half (14 pairs + 1 single), J3 = 10 (9 triples + 1 pair); no group touches symbols 0-6, 36-42 or 72-78; on a noiseless synthetic signal every set's 174 signs equal the codeword's bits; with the Gray map replaced by the identity (test-only hook or a test copy), J2 and J3 fail on that same signal.

### Stage 2: the product wiring (only after QA reports B1 PASS and the Architect rules)

6. **The walk.** In `cf_process_one` (`ft8_shim.c:2247`) and `ft8_coherent_fallback_process` (`:2634`): entered **only** when V3's BP gave no CRC-valid output (the NO_CRC state at `:2663-2665` in `_process`, `:2507-2509` in the serial `_run`; both paths get it). Never when V3 is CRC-valid (known, new, gated or gated out). Never on a candidate the fallback did not attempt. Order C1 -> J2 -> J3 -> N1, fixed; the first CRC-valid output ends the walk and then takes the **existing** path unchanged: KNOWN if its payload is in the snapshot's decoded list, otherwise SNR, F1b and the gate (`F1b <= CF_T1_DB`, `:2680-2683`; `_run` `:2527-2530`). **A known or gated-out payload is not retried with a later set.** BP only: `ftx_ldpc_decode_llrs` with `osd_depth` -1, `K_LDPC_ITERATIONS`, production normalisation, then CRC-14, exactly as `cf_run_bp` (`:2236-2244`), the raw values cast to float the same way. **No OSD.**
7. **Provenance.** Every fallback result records the set that produced its payload: 0 = V3, 1 = C1, 2 = J2, 3 = J3, 4 = N1, -1 none. Use the reserved `int32_t` at the end of `FT8CohFallbackOut` (`ft8_shim.h:1599`): no layout change. Also in the per-cycle counters. `ALL.TXT`, UDP and panel formats unchanged.
8. **The flag.** `decoder.coherentFallbackMultiSet`, **default `false`**, read once per cycle exactly as `coherentFallbackEnabled` is (`DecoderConfig.cs:240`, `Ft8Decoder.cs:197-214`, `Program.cs:807` and `:910`), acting only when `coherentFallbackEnabled` is true; config POST is an overlay (HK-035): a partial update leaves it as it was (test); **no Settings-page control**. It reaches native as a **per-call bit, not a process-global**: use `ft8_coherent_fallback_run`'s reserved `flags` (`ft8_shim.h:1609`). `ft8_coherent_fallback_process` has **no flags argument** (`ft8_shim.c:2634-2636`) and its context comes from the argument-less `ft8_coherent_fallback_ctx_new` (`ft8_shim.h:1638`): carry the same bit in the per-thread scratch context through an added setter; leave every existing signature unchanged; record the FILE:LINE of your choice in the commit.
9. **No mutable global state** in the per-candidate code (`coherent_fallback.c:28-31`): scratch in `cf_ctx_t` or on the stack. Parallel results stay deterministic (gathered in candidate order).
10. **Log line.** The per-cycle `Coherent fallback:` line (`Ft8Decoder.cs:1038`) gains aggregates only: `sets=on/off`, the number of candidates that entered the walk, CRC-valid counts per set. No message text.
11. **Flag OFF changes nothing:** identical native calls, outputs, counters (apart from added zeros) and order, with the fallback ON and with it OFF.
12. **Tests first, each able to fail:** (A1) characterisation: with the flag false, `ALL.TXT` lines, UDP datagrams, panel events and QSO-channel batches for a fixed set of recorded cycles are identical (outcome fields) to the build before this change, with the fallback ON and OFF. (M1) a native walk-entry test: on a fixed cycle the "candidates that entered the walk" counter equals the number of NO_CRC candidates of the same call; a V3-CRC-valid candidate and a not-attempted candidate show 0 walk entries and unchanged outputs against flag off. (B3) the existing row-by-row `_run` vs `_process` test (`tests/OpenWSFZ.Ft8.Tests/CoherentFallbackStep4NativeTests.cs:13`) passes the flag, with the sets ON, and compares the provenance row by row. Config overlay test for the flag.
13. **Linux and macOS binaries.** The committed `src/OpenWSFZ.Ft8/Native/linux-x64/libft8.so` and `osx-arm64/libft8.dylib` are refreshed by the usual follow-up chore after the native merge (PR #254 did it for 20260069). State the step in your report so QA does not meet a stale binary in CI.
